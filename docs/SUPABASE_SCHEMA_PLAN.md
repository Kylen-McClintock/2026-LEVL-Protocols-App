# LEVL Protocols App — Supabase Schema Plan

## Approach
- The MVP database will be deployed using Supabase PostgreSQL.
- **Authentication**: Intentionally omitted. `local_user_id` (a UUID string from `localStorage`) is used in place of `auth.users.id`.
- **Row Level Security (RLS)**: Not enforced for the MVP, or configured to allow anon read/write with a matching `local_user_id`, to avoid blocking demo usage.
- **Migrations**: We will use a single initial migration script `0001_initial_levl_protocols_schema.sql`.

## Tables

### `user_profiles`
- Primary Key: `id` (UUID)
- Fields: `local_user_id` (UNIQUE), `display_name`, `primary_goals` (array), `outcome_preference_scores` (jsonb), `health_conditions_text`, `medications_and_treatments_text`, `discipline_level_0_99`, `experimental_openness_0_99`, `weekly_time_budget_hours`, `weekly_spend_budget_usd`, `chronotype`, `risk_tolerance`, `longevity_personalization_coefficient` (numeric, default 1.0).

### `outcome_dimensions`
- Primary Key: `id` (text slug)
- Fields: `name`, `description`, `directionality`, `input_type`, `is_default_wellbeing`, `is_contextual`, `relevant_modality_types`, `goal_keys`.

### `modalities`
- Primary Key: `id` (text slug)
- Fields: `slug`, `name`, `modality_type`, `category`, `status`, `display_name`, `brief_description`, `expanded_why`, `headline_benefit`, `primary_outcome`, `secondary_outcomes`, `overall_longevity_benefit`, `implementation_summary`, `instructions`, `dose_or_exposure`, `timing_summary`, `frequency`, `schedule_pattern`, `difficulty`, `cost_tier`, `effort_level`, `time_to_benefit`, `evidence_quality`, `effect_size_estimate`, `evidence_summary`, `safety_level`, `safety_summary`, `contraindications`, `functional_outcomes_to_track`, `hallmarks_of_aging_impact` (jsonb), `mechanism_of_action`, `onset_profile`, `half_life_profile`, `ideal_cohort`, `contraindicating_cohort`, `relationships` (jsonb), `media_assets` (jsonb), `review_status`, `version`.

### `modality_variations`
- Primary Key: `id` (text slug)
- Relates to: `base_modality_id` -> `modalities(id)`
- Fields: Overrides for dose, timing, tracking, context of use, status.

### `protocols` & `protocol_steps`
- `protocols`: `id`, `name`, `goal`, `description`, `visibility`, `source_label`, `popularity_placeholder`, `review_status`.
- `protocol_steps`: `id`, `protocol_id`, `modality_id`, `variation_id`, `relative_time_archetype`, `frequency`, `required`, `ordering_index`, `notes`.

### `user_bench_items`
- Primary Key: `id` (UUID)
- Fields: `local_user_id`, `modality_id`, `variation_id`, `protocol_id`, `source`, `pinned`, `status`, `personal_notes`, `added_at`.

### `daily_sessions`
- Primary Key: `id` (UUID)
- Fields: `local_user_id`, `session_date`, `modality_id`, `variation_id`, `protocol_id`, `protocol_step_id`, `relative_time_archetype`, `status`, `completed_at`, `skipped_at`, `notes`.

### `outcome_observations`
- Primary Key: `id` (UUID)
- Fields: `local_user_id`, `session_id`, `outcome_id`, `phase`, `value_0_10`, `recorded_at`, `source_type`, `notes`.

### `daily_wellbeing_checkins`
- Primary Key: `id` (UUID)
- Fields: `local_user_id`, `checkin_date`, `mood_0_10`, `energy_0_10`, `stress_0_10`, `notes`.
- Unique constraint on `(local_user_id, checkin_date)`.

### Relationships & Claims
- `modality_relationships`: `modality_id`, `related_modality_id`, `relationship_type`, `notes`, `confidence`.
- `modality_claims`: `modality_id`, `variation_id`, `claim_text`, `claim_type`, `target_outcome`, `evidence_quality`, `effect_size_estimate`, `confidence`, `review_status`.
- `modality_sources`: `modality_id`, `claim_id`, `source_type`, `title`, `author`, `url`, `published_at`, `citation`.

## Future Migration Notes
- **Auth**: When Supabase Auth is integrated, a migration script will need to map existing `local_user_id` records in `user_profiles` to real `auth.users.id`. All dependent tables (sessions, bench, checkins) reference the `local_user_id` text column and will need an update or junction to transition ownership.
- **RLS**: Policies will be added in V1 to ensure `auth.uid() == user_profiles.auth_user_id`.
- **Storage**: Supabase Storage buckets will be provisioned in V2 for bloodwork PDFs and wearable exports.
- **AI Drafts**: New modalities generated by the AI Coach will populate these tables with `review_status = 'ai_drafted'` until promoted.
